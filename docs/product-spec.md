# Спецификация продукта

Документ описывает функциональность обеих сторон платформы **как она зафиксирована в кликабельных прототипах**. Прототипы — источник истины для технического задания на MVP.

- Клиентское приложение: [`prototypes/client-app/index.html`](../prototypes/client-app/index.html) (v1.5)
- Панель СТО: [`prototypes/sto-panel/index.html`](../prototypes/sto-panel/index.html)

---

## 1. Сквозная модель заказа

Обе стороны работают с одной сущностью — **заявкой (заказом)** — и видят один и тот же пятиэтапный трекер.

| # | Стадия | Что видит клиентка | Что делает СТО |
|---|---|---|---|
| 0 | **Принято** | «Машину забрали» | Подтверждает приём, начинает диагностику |
| 1 | **Диагностика** | «Мастер осматривает» | Описывает найденное, переходит к смете |
| 2 | **Смета** | «Согласование стоимости» — выбор запчасти, кнопка «Утвердить» | Формирует строки сметы, отправляет клиенту, ждёт согласования |
| 3 | **Ремонт** | «Идут работы», прогресс | Ведёт работы, отмечает завершение |
| 4 | **Готово** | «Можно забирать», оплата и оценка | Завершает заказ, получает выплату и рейтинг |

Ключевое правило приватности: **адрес и контакты клиентки скрыты в ленте заявок**, пока СТО не возьмёт заказ в работу.

## 2. Клиентское приложение (v1.5)

Мобильный интерфейс, 12 экранов. Нижняя навигация на 5 экранах: `home`, `offers`, `status`, `garage`, `profile`.

### 2.1 Карта экранов

| Экран (`id`) | Назначение |
|---|---|
| `screen-home` | Главная: активная машина, активный ремонт, кнопка «Рассказать, что случилось» |
| `screen-diagnose` | Описание проблемы: свободный текст + чипы симптомов |
| `screen-offers` | Лента предложений от СТО с постепенным раскрытием и фильтром по цене |
| `screen-confirm` | Подтверждение: способ подачи (автоконсьерж / самому), дата, слот, адрес |
| `screen-mappicker` | Выбор адреса по карте (сетка 3×3 с адресами Минска) |
| `screen-status` | Пятиэтапный трекер ремонта, смета, оплата, оценка |
| `screen-chat` | Чат с мастером (с индикатором набора текста) |
| `screen-garage` | «Мой гараж»: список автомобилей, плитка добавления |
| `screen-addcar` | Форма добавления автомобиля |
| `screen-car` | Профиль автомобиля: пробег, VIN, история ТО, напоминания |
| `screen-profile` | Профиль пользовательницы, привязанные карты |
| `screen-addcard` | Привязка банковской карты |

### 2.2 Подбор СТО (`offers`)

В прототипе 4 предложения, раскрываются по одному (`revealNextOffer`), сортируются по цене; самое дешёвое помечается как лучшее.

| СТО | Рейтинг | Расстояние | Цена | Запчасть в смете |
|---|---|---|---|---|
| Автосервис «Профсоюзная» | 4.9 | 1,4 км | 120 | Колодки передние (TRW, Германия) 80 + работа 40 |
| СТО «Мотор+» | 4.7 | 2,1 км | 135 | Колодки передние (Bosch, Германия) 90 + работа 45 |
| Гараж «На Некрасова» | 4.6 | 3,0 км | 99 | Колодки передние (Fenox, Россия) 60 + работа 39 |
| Автосервис «Скорость» | 4.8 | 0,8 км | 150 | Колодки передние (Brembo, Италия) 100 + работа 50 |

Фильтр по ценовым тирам (`low` / `medium` / `high`) вычисляется от средней цены предложений.

### 2.3 Прозрачная смета

Стоимость работы в прототипе фиксирована (`LABOR_COST = 45`), запчасть выбирается из выпадающего списка с указанием **цены, производителя и страны**; итог пересчитывается на лету. Это ядро ценностного предложения — клиентка видит, за что именно платит, и сама выбирает компромисс «цена / бренд».

### 2.4 Планирование подачи

- 8 дат вперёд (`buildDates`), 6 временных слотов: 08:00–10:00 … 18:00–20:00.
- Два режима: **автоконсьерж** (забирает водитель, показана карточка водителя — «Игорь, Chevrolet Cobalt, 4.9 ★») или **самостоятельная подача**.
- Адрес выбирается текстом или пином на карте.

## 3. Панель СТО

Десктопный интерфейс, 5 представлений, боковая навигация со счётчиками.

| Раздел | Назначение |
|---|---|
| **Новые заявки** | Лента заявок-карточек; фильтры: все районы / рядом (до 3 км) / на сегодня / срочные. Кнопка «Взять в работу» |
| **Мои заявки** | Список взятых заказов со статусом-пилюлей |
| **Детали заказа** | Трекер стадий, панель клиента, редактор сметы, действия по стадиям |
| **История** | Завершённые заказы: дата, звёзды, выплата |
| **Профиль СТО** | Рейтинг, число заказов, % в срок, специализация |

### 3.1 Карточка заявки в ленте

Содержит: модель авто, бейдж «Срочно»/«Новая», симптом (обрезается до 90 символов), теги симптомов, район и расстояние, слот, время публикации, вилку ориентировочной цены.

**До взятия в работу скрыты:** имя клиента, телефон, точный адрес. В раскрытой карточке на их месте — плейсхолдер «доступно после взятия в работу».

### 3.2 Редактор сметы

Строки «название + цена» с автоподсчётом итога, добавление позиций, отправка клиенту и ожидание согласования (`sendEstimate` → «Смета отправлена клиенту, ждём согласования»).

## 4. Дизайн-система

Обе стороны используют одну визуальную идентику.

| Токен | Значение | Роль |
|---|---|---|
| `--ink` | `#1B2430` | Основной текст, сайдбар |
| `--ink-soft` | `#4D5769` | Вторичный текст |
| `--ink-faint` | `#8891A0` | Подписи, мета |
| `--paper` | `#F6F4EF` | Фон приложения |
| `--card` | `#FFFFFF` | Карточки, панели |
| `--amber` | `#E8A33D` | Основное действие, акцент |
| `--copper` | `#B5602C` | Градиенты прогресса |
| `--teal` | `#3F7D6B` | Успех, завершение |
| `--alert` | `#C1503F` | Срочное, ошибки |
| `--line` | `#DEDACE` | Границы |

**Шрифты:** Space Grotesk (заголовки), Inter (текст), IBM Plex Mono (цифры, статусы, цены).

## 5. Известные расхождения в прототипах

Зафиксированы как есть; решения по ним — в бэклоге на Trello.

| # | Расхождение | Детали |
|---|---|---|
| 1 | **География панели СТО** | Панель СТО использует московские адреса (Москва, Тверской, Хамовники, Ленинский пр-т, Комсомольский пр-т), тогда как бизнес-план и клиентское приложение ориентированы на Минск (Немига, Победителей, Заславская) |
| 2 | **Валюта** | В прототипах цены в `Br` (BYN), в бизнес-плане и финансовой модели — в USD. Нужно решение: витринная валюта BYN + расчётная USD |
| 3 | **Данные — моки в памяти** | Оба прототипа держат состояние в JS-переменных; при перезагрузке всё сбрасывается. Нет API, нет персистентности |
| 4 | **Нет связи между сторонами** | Заявка, взятая в панели СТО, не отражается в клиентском приложении — это два независимых файла |
| 5 | **Нет аутентификации** | Ни входа, ни ролей, ни разделения аккаунтов |
| 6 | **Оплата — имитация** | Форма карты без платёжного провайдера; по плану требуется сертифицированный провайдер без хранения данных карт на стороне приложения |

## 6. Что нужно для MVP сверх прототипов

1. **Бэкенд и модель данных** — пользователи, автомобили, заявки, СТО, сметы, платежи, рейтинги.
2. **Реальный обмен статусами** между клиентским приложением и панелью СТО.
3. **Аутентификация и роли** — клиентка, СТО, диспетчер, автоконсьерж.
4. **Платёжный провайдер** — приём карт без хранения данных на своей стороне (см. регуляторный риск в бизнес-плане).
5. **Подписки** — биллинг $100/мес для СТО и $6,5/мес для клиенток, с пробным периодом для СТО.
6. **Диспетчерский инструмент** — назначение автоконсьержей, эскалация споров (в MVP процесс ручной, см. раздел 6.4 бизнес-плана).
7. **Модерация и онбординг СТО** — проверка документов, осмотр, приоритет в ленте по рейтингу.
