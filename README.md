# Мой автомеханик — экосистема

Четыре приложения работают на одном сервере и видят одни и те же заказы в реальном времени:

| Приложение | Кто пользуется | Где работает | Папка |
|---|---|---|---|
| **Мой автомеханик** | клиентка | Android, iOS, веб | `apps/client`, `mobile/client` |
| **Консьерж** | водитель, который перегоняет машину | Android, iOS, веб | `apps/concierge`, `mobile/concierge` |
| **Панель СТО** | станция техобслуживания | веб | `apps/sto` |
| **Панель диспетчера** | диспетчер и директор | веб | `apps/dispatcher` |

Интерфейсы взяты из прототипов (клиентка v1.9, СТО v1.6, диспетчер, консьерж) без перерисовки. Демо-данные из прототипов заменены живыми данными с сервера.

## Быстрый старт

Нужен Node.js 22.5 или новее: используется встроенный SQLite.

```bash
cd server && npm install && npm start
```

Откройте http://localhost:8080/. Там страница экосистемы: все четыре приложения рядом и лента событий. Каждое приложение можно открыть и отдельно: `/client/`, `/concierge/`, `/sto/`, `/dispatcher/`. Если открыть их на разных устройствах в одной сети, они тоже синхронизируются.

Кнопка «Сбросить демо» возвращает стартовые данные.

## Как заказ проходит через все приложения

```
Клиентка             СТО                    Консьерж                Диспетчер
─────────            ───                    ────────                ─────────
заявка ───────────▶ лента «Новые заявки»
                     предложение цены ───▶ (клиентке)
выбор СТО ─────────▶ «Мои заявки»   ──────▶ лента заказов ────────▶ «ждёт консьержа» / назначить
карта: консьерж едет ◀─────────────────────── шаги поездки, позиция
акт №1: подтвердить ◀──────────────────────── акт №1
                     акт №2: принять ◀─────── акт №2
статус «Диагностика» ◀ стадии
смета: одобрить ◀──── смета
                     «Готово» ────────────▶ заказ на возврат
                     акт №3 ──────────────▶ везёт клиентке
акт №4, оплата, оценка ◀───────────────────── акт №4
«Есть претензия» ─────────────────────────────────────────────────▶ спор → директор → возврат
SOS / эвакуатор ──────────────────────────────────────────────────▶ SOS 24/7
```

Чат по заказу общий: клиентка, мастер СТО, консьерж и диспетчер видят одну переписку. Уведомления приходят в каждое приложение. На телефоне, когда приложение свёрнуто, они показываются как системные.

### Демо-боты

Чтобы сценарий проходил, даже если открыто одно приложение, сервер управляет «ботами»:

- три других СТО («Мотор+», «На Некрасова», «Скорость») присылают свои цены на заявку клиентки;
- клиентки-боты выбирают предложение вашей СТО, одобряют смету и платят;
- консьержи Дмитрий, Сергей, Алексей и Павел сами проходят шаги, если диспетчер назначил их на заказ.

Живые пользователи: клиентка **Анна Иванова** (`c1`), СТО **«Автосервис на Независимости»** (`sto1`), консьерж **Игорь** (`k1`) и диспетчер. Войти от имени другого участника можно параметром `?as=`, например `/concierge/?as=k3`.

## Архитектура

```
apps/                    веб-приложения (статические HTML/JS)
  shared/ma-sdk.js       общий SDK: WebSocket-синхронизация, действия, уведомления, адрес сервера
  client/  client-sync.js        прототип v1.9 и слой синхронизации
  sto/     sto-sync.js
  dispatcher/ dispatcher-sync.js
  concierge/  concierge-app.js
  index.html             страница экосистемы
server/
  src/seed.js            общие стартовые данные для всех приложений
  src/domain.js          бизнес-логика: жизненный цикл заказа, акты, споры, SOS, боты, права видимости
  src/index.js           HTTP, REST, WebSocket, статика
  src/store.js           SQLite: снимок состояния и журнал событий
  test/flow.test.js      сквозные тесты логики
mobile/
  client/, concierge/    проекты Capacitor 8 (android/, ios/)
  scripts/build-www.mjs  собирает веб-часть приложения из apps/ в www/
```

- **Протокол.** Приложение отправляет `hello {role, id}` и получает `state`: представление данных для своей роли. Действие уходит как `act {type, p}`, после него всем рассылается новое `state` и адресные `notify`. Позиция консьержа в поездке идёт отдельными лёгкими сообщениями `loc`.
- **Приватность.** СТО видит телефон и адрес клиентки только после того, как клиентка выбрала эту станцию. Консьерж видит их только после того, как взял заказ. Это проверяется на сервере, в `viewFor`.
- **REST** для интеграций: `GET /api/state?role=&id=`, `POST /api/act`, `POST /api/reset`, `GET /api/events`, `GET /api/health`.

## Мобильные приложения (Android и iOS)

```bash
cd mobile && npm install
MA_SERVER_URL=https://ваш-сервер npm run sync    # веб-часть из apps/ → www → нативные проекты
npm run open:client:android                      # Android Studio
npm run open:client:ios                          # Xcode (на Mac)
```

- Без `MA_SERVER_URL` приложения подключаются к локальному серверу: на Android-эмуляторе это `http://10.0.2.2:8080`, на iOS-симуляторе `http://localhost:8080`. Адрес можно сменить прямо в приложении: нажмите на индикатор связи вверху экрана.
- Для HTTP-сервера в демо разрешён незашифрованный трафик (`usesCleartextTraffic`, `NSAllowsArbitraryLoads`). Для публикации в магазины нужен HTTPS, а эти исключения надо убрать.
- Разрешения: геопозиция (маршрут до СТО у клиентки, трансляция поездки у консьержа), уведомления, камера (акты у консьержа).
- Идентификаторы: `by.moyavtomekhanik.app` и `by.moyavtomekhanik.concierge`. Иконки и заставки лежат в `mobile/*/assets`, перегенерировать их можно командой `npx @capacitor/assets generate`.

### CI-сборки

Workflow `.github/workflows/build.yml` на каждый push:

- запускает тесты сервера;
- собирает **Android APK** (debug) для обоих приложений;
- собирает **iOS** для симулятора и неподписанный `.ipa` для устройства, на macOS-раннере.

Готовые файлы скачиваются в Actions → Artifacts. Адрес сервера задаётся переменной репозитория `MA_SERVER_URL` или полем при ручном запуске.

### Что нужно для публикации в Google Play и App Store

1. Развернуть сервер с HTTPS. В репозитории есть `Dockerfile`: `docker build -t ma . && docker run -p 8080:8080 -v ma-data:/data ma`.
2. Android: ключ подписи (keystore), сборка `./gradlew bundleRelease`, аккаунт Google Play Console.
3. iOS: аккаунт Apple Developer, сертификат и provisioning profile, архив через Xcode или `xcodebuild archive`.
4. Push-уведомления в фоне через FCM и APNs. Сейчас уведомления приходят, пока приложение открыто или свёрнуто, но живо. Закрытое приложение их не получит.
5. Авторизация пользователей: телефон и SMS-код. Сейчас роль выбирается параметром — это демо.
